# 性能排查记录（2026-09-21）

现象：工作台「每次点击都要等很久」，且随任务数增长越来越慢。
本文件只记录**实测数据与候选方案**，优化尚未实施（待做）。

## 1. 实测数据

环境：本机 SQLite 库 `data/runtime/audit_tasks.sqlite3`，
任务 **1156** 条（CREATED 668 / READY 2 / COMPLETED 480 / FAILED 6）、
文件 1410 行、复核项 510 行、审计事件 3543 行、库大小 4.3 MB。

| 环节 | 实测耗时 | 说明 |
| --- | --- | --- |
| 工作台每次 rerun 都会调用的 `task_store.list_tasks()` | **1367 ms** | 全量 1156 条，逐条再查文件/复核项（N+1），481 条还要反序列化报告 |
| 同等数据的精简 SQL（只取展示需要的列） | **4 ms** | 差距 340×：瓶颈是查询方式，不是数据量 |
| `GET /api/v1/audit-tasks` | **7300–7800 ms** | 返回 322 KB；全量 + N+1 + Pydantic 序列化 |
| 状态统计（SQL `GROUP BY` 对照） | **1 ms** | 现在是在 Python 里遍历 1156 个对象统计 |
| `task_store.require_task()`（详情页） | **1 ms** | 单条查询本身没问题，无需优化 |
| 表格渲染 | 数百 ms | 1156 行 DataFrame；且 `on_select="rerun"`，点行即整页重跑 |
| 百度 OCR（审核时，单次调用） | **1238 ms** | 正常范围 |
| DeepSeek 调用（审核时） | **3252 ms/次** | JSON 校验失败会重试，最多 2 次 → 最坏约 6.5 s |
| 本地六项确定性检查 | 约 7 ms | 可忽略 |

根因：**每次点击都把全部任务连同文件、复核项、报告重查重算一遍**，成本随任务数线性增长
（当前库里绝大多数任务来自开发期测试，属于可清理的噪音数据）。

复现方式：

```powershell
# 1) 列表查询耗时与任务规模
.\.venv\Scripts\python.exe -c "import time;from app.api.store import task_store;t=time.perf_counter();n=len(task_store.list_tasks());print(n, (time.perf_counter()-t)*1000, 'ms')"
# 2) 接口耗时
curl.exe -s -o NUL -w "%{time_total}s`n" http://127.0.0.1:8000/api/v1/audit-tasks
```

## 2. 候选方案（按性价比排序，均未实施）

| # | 方案 | 改动量 | 预期收益 | 代价/风险 |
| --- | --- | --- | --- | --- |
| ① | 清理历史数据：删掉空任务（CREATED 且无文件）与过旧测试任务，只保留最近数十条 | 零代码 | 列表立即快 20–30× | 无（数据是测试残留，可先导出） |
| ② | 列表查询重构：一条 SQL 取摘要（实测 4 ms）、状态/风险数用聚合、分页（默认最近 50 条）+ 服务端筛选、SQLite 加索引/WAL/连接复用 | 中等 | 点击 1367 ms → **<50 ms**；接口 7.8 s → **<100 ms** | 需改 store 与接口层，注意 KB 级契约不变 |
| ③ | 缓存：`st.cache_data(ttl=3~5s)` 缓存列表与统计，写操作后主动失效 | 小 | 连续点击近乎瞬开 | 新鲜度延迟数秒 |
| ④ | 渲染：只渲染当前页；`on_select="rerun"` 改为"选中后点按钮打开" | 小 | 渲染数百 ms → 数十 ms，减少无谓 rerun | 交互多一步 |
| ⑤ | 审核运行后台化：点击立即返回"审核中"，前端轮询节点进度（百度识别 → 模型抽取 → 六项检查）；或同步 + 阶段进度条；并削峰（`MODEL_EXTRACTION_MAX_ATTEMPTS` 2→1、DeepSeek `response_format=json_object`） | 中等 | 点击响应 5–9 s → 立即；每次审核省 3–6 s | 后台化会改 API/前端契约（新增运行中状态与进度查询），需先定契约 |
| ⑥ | 环境：Streamlit 关文件监听（`--server.fileWatcherType none`，当前监视含 1410 个上传文件的目录） | 零代码 | 减少无谓重载 | 热重载失效 |

建议组合：**① + ② + ③ + ④**（点击进入 100 ms 内）；若还要消除"运行审核"的等待，再加 ⑤。

## 3. 待确认

- 用户感受到的"卡"主要在**切页面/点任务**，还是**点「运行审核」**？前者优先做 ②③，后者优先做 ⑤。
- ⑤ 的后台化涉及接口契约（新增任务"运行中"状态 + 进度查询），按协作约定需与协作者 评审后再动。
